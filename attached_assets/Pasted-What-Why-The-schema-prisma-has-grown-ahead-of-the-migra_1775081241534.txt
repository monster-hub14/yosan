What & Why
The `schema.prisma` has grown ahead of the migration history. Several tables and columns that exist in the schema are absent from the database after `prisma migrate deploy`, causing runtime crashes with errors like “column does not exist.”
This task must use Prisma’s normal migration flow first so Prisma generates SQL from the real schema instead of guessing by hand.

Done looks like

* A new migration folder exists under `prisma/migrations/` created by Prisma
* `prisma migrate status` reports no pending migrations and no drift
* The app starts without any “column does not exist” runtime errors
* No data is dropped or reset

Out of scope

* Changing business logic
* Seeding data
* Any destructive operation such as dropping tables or resetting the DB

Tasks

1. Run Prisma migration generation from the app directory.
   First try the workspace command:

```bash
pnpm --filter @workspace/budget-app exec prisma migrate dev --name add_missing_schema_fields
```

If that fails because the workspace filter is wrong, then run from the actual app directory instead:

```bash
cd artifacts/budget-app
pnpm exec prisma migrate dev --name add_missing_schema_fields
```

2. If `prisma migrate dev` fails, inspect the exact error output.
   Only then create the minimum manual migration needed for the specific SQLite limitation Prisma cannot handle automatically. Do not write a large hand-made migration unless Prisma proves it is necessary.

3. Verify the result by running:

```bash
pnpm --filter @workspace/budget-app exec prisma generate
pnpm --filter @workspace/budget-app exec prisma migrate status
```

If the workspace filter fails, run instead from `artifacts/budget-app`:

```bash
cd artifacts/budget-app
pnpm exec prisma generate
pnpm exec prisma migrate status
```

4. Smoke test the app.
   Start the app and confirm there are no runtime errors for missing columns, especially around:

* AI settings / AI provider config
* category creation and category views
* onboarding / account setup

Expected missing fields for verification only
Do not pre-write SQL from this list. Use it only to confirm the generated migration includes the missing schema changes:

* `Category.sortOrder`
* `AIProviderConfig.extractionEnabled`
* `AIProviderConfig.categorizationEnabled`
* `AIProviderConfig.recurringCategorizationEnabled`
* `AIProviderConfig.insightsEnabled`
* `AIProviderConfig.forecastingEnabled`
* `AIProviderConfig.dailyLimitPerUser`
* `AIProviderConfig.weeklyLimitPerUser`
* `AIProviderConfig.monthlyLimitPerUser`
* `Expense.addedById`
* `Expense.currency`
* `PendingImport.expenseId`
* `PendingImport.confirmedById`
* `PendingImport.confirmedAt`
* `ClarificationHistory.context`
* `ClarificationHistory.receiptId` nullable change
* `ItemMemory.isAmbiguous`
* `ItemMemory.ambiguousQuestion`
* new tables such as `AIUsageLog`, `UserAIControl`, and `CategoryTarget`

Important
After the migration is created successfully, commit and push:

* updated `prisma/migrations/...`
* any Prisma client updates if generated in tracked files

Then rebuild and redeploy the Docker image so TrueNAS pulls the fixed image.
